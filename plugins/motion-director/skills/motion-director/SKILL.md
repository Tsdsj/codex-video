# 动效视频导演

把视频当作有时间结构的作品：明确观众要理解什么，再让构图、运动、声音共同完成表达。不要把“高级”翻译成堆叠特效。

## 按当前阶段进入

- 用户只要研究、方案或分镜：交付该阶段；不擅自安装渲染环境或制作成片。
- 新视频：整理 Brief 和可查看的关键画面/分镜。沿用用户及项目的设计确认要求；已有确认方案直接使用，已有实施授权不重复询问。
- 已有视频需要修正：先定位镜头和帧号，保留已确认风格，修正对应原因，不重做整片。
- 只做审查：提供时间码、问题和建议，不修改素材或代码。

## 1. 建立导演上下文

从已有需求提取受众、用途、核心信息、时长、画幅、帧率、投放场景、品牌、素材、声音要求和交付格式。只问会改变方向的缺失信息；常规细节可提出明确假设。

用 [制作模板](references/production-template.md) 记录必要内容，短片可以合并文档。不要为了填模板虚构素材或目标。

有参考时，实际查看可访问的画面，拆解构图、色彩、材质、镜头、运动阶段、停顿和转场机制。区分看到的事实与自己的推断；无法读取或播放时明确说明。参考用于提取规律，素材的再使用需要核对授权。

无参考时，基于品牌和表达目标提出一套克制的方向，给出关键帧或粗剪供查看。不要默认为霓虹、玻璃、全屏大字或弹跳。风格约束说明“为什么”，不把某种审美当作普遍禁令。

## 2. 把信息编排成时间

每个镜头设一个主要表达任务，定义视线落点、主事件、阅读停留和转场承接。镜头长度由内容决定，不机械规定镜头数量。

有音乐时建立拍点表；无音乐、旁白主导或无障碍静音交付时按语义节奏组织，不强加 BGM。

- 恒定节拍间隔：`framesPerBeat = fps * 60 / BPM`。
- 拍点：`round((offsetSeconds + beatIndex * 60 / BPM) * fps)`；逐个计算，避免累计舍入漂移。
- 120 BPM、60 fps 时一拍 30 帧只是例子，不是项目默认。
- 重点动作可贴合强拍；留白、停顿和弱拍承接同样重要，不要求每拍都有动作。
- 镜头范围统一用半开区间 `[startFrame, endFrame)`；总帧数、首尾帧和声音时长一起核对。

## 3. 让运动有因果、有主次

定义主体、辅助元素、背景和相机各自的作用。它们可以共享主时钟，但不能无理由地共享同一进度曲线、相位和振幅。让辅助运动回应主事件，同一时刻避免多个同权重焦点。

需要表现重量或接触时，考虑预备、加速、接触、形变和衰减回稳；选择符合材质的部分，不给所有元素套完整弹跳序列。

- 位置、速度、旋转和缩放的交接应连续，或明确使用有意的剪切。
- 拉伸、挤压、过冲来自速度、冲量和材质；不要随机弹簧化文字和相机。
- 自由飞行可用重力模型，弹性回稳可用阻尼模型；艺术化运动也要内部一致。
- 阴影和反射由主体、表面、光源决定。装饰性回声/尘埃可以延迟，物理接触影不可机械滞后。
- 背景只在帮助深度、方向或情绪时运动；静止是有效选择。
- 用稳定的光照和材质关系建立层次。静止物体在固定灯光下无需强行动高光。

## 4. 选择可复现的实现

先检查已有项目、工具与版本，沿用技术栈。React 视频工程可使用 Remotion，简单图形可使用 SVG/Canvas，真正需要空间相机和材质时再选 3D。不要仅因文章提过某工具就安装它。

**用户选择 Remotion，或新建可编程视频且没有既定渲染方案时**：读取 [Remotion 制作指南](references/remotion.md)。新项目优先考虑此路线；已有可用工程不强制迁移。插件附带可复制到项目中的 [Remotion 起步工程](assets/remotion-starter/README.md)，包含确定性运动、本地渲染和抽帧验证。不要在已安装插件缓存内安装依赖或制作作品。

用户要求精致、高级、流畅或现有作品像 PPT 时，读取 [视觉与运动判断](references/art-direction.md)，将具体问题映射到构图、时间、空间连续性和运动机制，不能只换 easing。

新依赖或具体 API 写法以当前官方文档为准。优先本地渲染和现有素材；外部生成服务要说明费用、依赖及可用的本地替代，遵守已有预算和授权。

让画面状态由帧号/时间和固定种子决定；避免渲染依赖墙钟、未固定随机数或未完成的字体/图片加载。把时间参数与视觉参数分开，便于只调整节奏。

先实现代表性镜头或低成本粗剪，验证构图、连续性和节奏，再扩展与高质量导出。优化效果依据实际画面，不以代码行数、特效数量或模型名作为质量指标。

## 5. 将声音绑定到事件

制作有声视频或修正音效时，读取 [免费本地声音流程](references/sound-design.md)。这是插件默认声音路线：使用已授权的免费素材或原创本地合成，禁止自动转向付费 API、试用额度或需要订阅的音源。附带 24 个原创合成音效、8 个 CC0 候选素材、事件清单示例和本地混音脚本；素材仍需试听选择。

音效表标明素材、事件、起始帧、峰值/接触帧、长度和音量。运动扫过、碰撞、碎屑、环境声各有作用，不用同一个 whoosh 覆盖所有动作。

接触音的可感知瞬态应对准画面接触；预备声和余响可前后展开，素材前导静音需要补偿。音乐支持段落，旁白优先清晰。静音需求直接输出静音版本。

核对素材许可；缺素材时可以先用标注清楚的占位或已授权的本地合成声音，不把占位当最终混音。

## 6. 验证成片，而不只验证代码

按 [验收清单](references/quality-review.md) 进行技术、画面、运动、声音检查。通过构建或成功导出不等于视觉验收。

实际播放有声版本检查节奏与声画同步；抽查首尾帧、切点、接触点、最大形变及回稳帧。静帧图集不能证明运动流畅或声音正确。工具不能播放/听音时，保留证据并标注未验证项。

必要时制作独立 HTML 检查页，显示渲染帧、帧号、时间码、镜头和事件，支持逐帧前后切换。普通视频 seek 不是严格逐帧证据；需要精确检查时用实际导出的帧序列或渲染器帧 API。

优先修复信息不可读、黑帧/漏帧、跳变、穿模、声音错位，再调整装饰细节。修复后只重验相关镜头及其相邻过渡；无法完成的检查明确交接。

交付视频文件、可复现工程、实际运行的导出命令、关键参数和简短验收结果。仅方案任务交付方案即可，不夸大成片状态。
